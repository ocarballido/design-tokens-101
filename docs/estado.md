## Hallazgos que afectan a otros frentes

- **2026-10-05: Modos en Figma (sesión de contenido, para el módulo 5).** Prueba con la API de plugins en TokensDS (colección temporal "TMP modos prueba" y nodos temporales, borrados al terminar; las colecciones del archivo no cambian). (1) Una colección nueva creada con la API tiene un modo llamado `Mode 1`. (2) `addMode` copia en el modo nuevo los valores del primer modo: un alias sigue siendo alias al mismo primitivo y un valor directo se copia tal cual (la ayuda de Figma dice que se duplican los valores de la primera columna). (3) Sin modo elegido, todo usa el modo por defecto (el primero). (4) Un modo elegido en un marco lo heredan sus hijos y los marcos anidados (los hijos siguen en Auto, sin modo propio); un marco anidado puede elegir otro. (5) Un modo elegido en la página lo heredan los marcos sin modo. (6) Una instancia hereda el modo del marco donde está, **salvo que el componente principal tenga un modo elegido**: entonces la instancia toma el del componente. (7) Un texto con el tamaño vinculado a `font-size/heading/1` (Layout) mide 40 sin modo (Desktop es el modo por defecto), 32 en Mobile y 40 en Desktop. (8) Al borrar un modo que usa un marco, el marco conserva la referencia y sus elementos pasan al modo por defecto. Exportación: la ayuda documenta *Export mode* y *Export modes*; la exportación real del repositorio (`tokens/figma/`) tiene un archivo por modo con todas las variables de la colección, alias resueltos con `com.figma.aliasData` y el nombre del modo en `com.figma.modeName`. Las plantillas de TokensDS eligen el modo de las dos colecciones en el marco de cada pantalla (`Semantic color` y `Layout`).
- **2026-10-04: Color con opacidad en la exportación DTCG de Figma (sesión de desarrollo).** Primera variable con transparencia del sistema. Light: `{ "colorSpace": "srgb", "components": [1, 1, 1], "alpha": 0.8999999761581421, "hex": "#FFFFFF" }`; Dark: `components` `[0.0196…, 0.0470…, 0.0352…]`, mismo `alpha`, `"hex": "#050C09"`; `overlay`: `components` `[0, 0, 0]`, `"alpha": 0.5`, `"hex": "#000000"`. (1) El `alpha` va en su campo y en float32: un 90 % no es exacto (0,9 → 0,8999999761581421). (2) `hex` tiene seis cifras, sin la opacidad. (3) Sin corregir, el CSS sale `#ffffffe5` (89,8 %) en vez de `#ffffffe6`; el normalizador recupera `0.9` (V31). (4) El tipo sigue siendo `color` y se normaliza sin cambios en el resto.
- **2026-09-30: Color en Figma.** La importación DTCG de Figma solo admite color en sRGB y HSL, dimensiones en `px`, duraciones en `s` y la familia tipográfica como un único nombre (Figma: Modes for variables).
- **2026-09-30: DTCG.** La versión 2025.10 (Format, Color y Resolver) es un *Final Community Group Report* del 28/10/2025. No es un estándar del W3C, pero se declara estable.
- **2026-09-30: npm.** En el entorno de la sesión de contenido, el registro de npm devuelve 403. Si pasa lo mismo en desarrollo, el build habrá que hacerlo en local o en Vercel.
- **2026-09-30: MCP de Figma usa el code syntax (sesión de diseño).** `get_design_context` escribe las variables con su code syntax Web y un valor de reserva: `gap-[var(--t101-space-200,8px)]`. Material para el módulo 10.

- **2026-10-04: `$ref` y la opacidad (sesión de contenido).** La regla 6 (§5.2) y V25/V28 dicen que "un alias no puede cambiar la opacidad". Es exacto para Figma y para la sintaxis de llaves de DTCG, pero DTCG 2025.10 tiene `$ref` (JSON Pointer), que puede tomar los `components` de otro color y fijar un `alpha` propio (ejemplo del [Format Module](https://www.designtokens.org/TR/2025.10/format/#json-pointer-syntax-required-support)). - **2026-10-04: Modo del destino en un alias entre colecciones (sesión de contenido).** Prueba con la API de plugins en TokensDS (colecciones temporales, borradas): una variable de la colección B apunta a otra de la colección A, que tiene dos modos. Sin modo explícito, el alias usa el modo por defecto de A; con el segundo modo de A elegido en el marco o en el propio elemento, usa ese modo. La ayuda de Figma no lo documenta. Reflejado en `semantic-collections`.
- **2026-10-04: `$ref` en Terrazzo (sesión de desarrollo).** Pregunta: ¿Terrazzo 2.7 admite `$ref` (JSON Pointer) de DTCG 2025.10 para tomar los `components` de `color/black` con otro `alpha`?
  - **Lo que dicen las fuentes.** El Format Module admite `$ref` dentro de un valor, también a una parte (`#/colors/blue/$value/components/0`), y el puntero se resuelve contra el documento actual; no habla de referencias entre archivos ([Format Module: JSON Pointer syntax](https://www.designtokens.org/TR/2025.10/format/#json-pointer-syntax-required-support)). La documentación de Terrazzo solo trata `$ref` en los Resolvers ("$ref can be used to point anywhere", [Terrazzo: Resolvers](https://terrazzo.app/docs/guides/resolvers)) y, en los valores, las llaves (`"{color.gray.900}"`); ni [Token Types](https://terrazzo.app/docs/reference/tokens/) ni [DTCG Tokens](https://terrazzo.app/docs/guides/dtcg/) mencionan `$ref` dentro de un token. **No está documentado.**
  - **Lo comprobado por prueba** (copia fuera del repositorio, `@terrazzo/cli` y `plugin-css` 2.7.1, `legacyHex`): `"components": { "$ref": "#/color/black/$value/components" }` con `"alpha": 0.5` da `--color-overlay: #00000080`. (1) En un solo archivo, funciona. (2) Con dos archivos unidos por un Resolver (el negro en uno y el overlay en otro, como `tokens101.resolver.json`), también funciona: Terrazzo resuelve el puntero contra el conjunto unido, algo que el Format Module no describe. (3) Si el negro pasa a rojo, el overlay pasa a `#ff000080`: el valor se deriva de verdad. (4) Un puntero roto detiene el build ("Can't find $ref"). (5) El parser lo registra como `partialAliasOf: { components: "color.black" }`, pero `plugin-css` escribe un **valor fijo**, no `var(--t101-color-black)`: en el CSS se pierde la relación.
  - **Recomendación:** no adoptarlo ahora (S32). Funciona, pero no está documentado (mismo riesgo que V09), Figma no lo exporta (habría que escribirlo en los tokens solo de código) y el CSS final es el mismo valor directo. Si se adoptara, haría falta una prueba en `npm run check:tokens` que lo vigile.
