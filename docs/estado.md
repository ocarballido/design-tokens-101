  - **Lo que dicen las fuentes.** El Format Module admite `$ref` dentro de un valor, también a una parte (`#/colors/blue/$value/components/0`), y el puntero se resuelve contra el documento actual; no habla de referencias entre archivos ([Format Module: JSON Pointer syntax](https://www.designtokens.org/TR/2025.10/format/#json-pointer-syntax-required-support)). La documentación de Terrazzo solo trata `$ref` en los Resolvers ("$ref can be used to point anywhere", [Terrazzo: Resolvers](https://terrazzo.app/docs/guides/resolvers)) y, en los valores, las llaves (`"{color.gray.900}"`); ni [Token Types](https://terrazzo.app/docs/reference/tokens/) ni [DTCG Tokens](https://terrazzo.app/docs/guides/dtcg/) mencionan `$ref` dentro de un token. **No está documentado.**
  - **Lo comprobado por prueba** (copia fuera del repositorio, `@terrazzo/cli` y `plugin-css` 2.7.1, `legacyHex`): `"components": { "$ref": "#/color/black/$value/components" }` con `"alpha": 0.5` da `--color-overlay: #00000080`. (1) En un solo archivo, funciona. (2) Con dos archivos unidos por un Resolver (el negro en uno y el overlay en otro, como `tokens101.resolver.json`), también funciona: Terrazzo resuelve el puntero contra el conjunto unido, algo que el Format Module no describe. (3) Si el negro pasa a rojo, el overlay pasa a `#ff000080`: el valor se deriva de verdad. (4) Un puntero roto detiene el build ("Can't find $ref"). (5) El parser lo registra como `partialAliasOf: { components: "color.black" }`, pero `plugin-css` escribe un **valor fijo**, no `var(--t101-color-black)`: en el CSS se pierde la relación.
  - **Recomendación:** no adoptarlo ahora (S32). Funciona, pero no está documentado (mismo riesgo que V09), Figma no lo exporta (habría que escribirlo en los tokens solo de código) y el CSS final es el mismo valor directo.
